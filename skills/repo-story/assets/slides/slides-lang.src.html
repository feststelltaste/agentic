Origin story

An editor that agents can operate too

How a Photoshop clone came into being in nine days: in what order, under which rules, and what the developers did every time something went wrong.

Act 1 · Scaffold

Hour three: 42,241 lines and a decision

Commit no. 2, “one-shot”: layers, masks, compositor, PSD reader, 971 tests, all green when we built it.

Four decisions that carry everything

  • One list is the interface. Every action is a command in one registry.
  • The UI is a thin client on top of that registry.
  • The agent gets perception: the document as JSON, screenshots as images.
  • Built in on day 2: a windowless JSON server and an MCP server.

Layer rules were checked by a tool from the first hour. An agent does not like to re-read rules, so the build enforces them.

Act 3 · Robustness

Never crash again

Rule 9 enters AGENTS.md: no input may crash a command. Fourteen minutes later a fuzz test calls every command with hostile parameters.

2,085normal tests: all green
4 TBof memory requested by the fuzz test, by moving a selection far off-canvas

No normal test would have found it. Eight hours later: “Found by the panic_hunt fuzz.” After that the rule became compiler configuration, and agent access got a token and allow-listed directories.

The manual for agents

AGENTS.md: mechanics, not wishes

  • Read the honest situation first. The parity floor may only rise, never fall.
  • A fixed closing list: tests, Clippy, layer check, WASM check, fuzz test, corpus.
  • A dev log for sessions that break off. Log plus green tree let the next agent carry on.
  • Parallel agents: own build directory each, new commands in new modules, no repairing someone else's half-finished work.

Compiler as guard

The file-format library stops compiling when the document model gains a field. Nothing can be silently lost on save.

The pattern

Every mishap became a check, not a warning

A crash→a fuzz test
“Looks right”→a pixel oracle
Red formatting→a CI step
Broken layering→a build failure
Agent file access→an allow-list

Agents may be fast, but they cannot get far without something tripping. Where a check was missing, it showed: community tests did not compile as long as nobody compiled them.

What we take away

Five questions for your own product

  1. Is there a layer through which an agent can do everything a human does in the UI?
  2. Is our interface a thin client on top of it?
  3. Can an agent perceive our system: structured state and images, or does it guess?
  4. How do we secure its access?
  5. Do we have an acceptance test that really plays through flows with agents?
